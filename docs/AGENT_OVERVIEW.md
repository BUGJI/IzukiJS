# Izuki JS · 面向 AI Agent 的功能与开关总览

[返回文档索引](README.md)

本文给外部 AI Agent 快速建立心智模型：这个程序是什么、界面上有什么、每个开关控制什么、
打开或关闭后会影响哪些脚本 API 与设备行为。**它不是脚本 API 或 MCP 工具手册**，
具体参数与返回值请分别看 [SCRIPT_API.md](SCRIPT_API.md) 与 [MCP.md](MCP.md)。

> 适用对象：需要替用户配置本应用、诊断「为什么脚本没生效」、或通过 MCP 操作设备的 Agent。

## 0. 四层开关模型

Izuki JS 是 Android 上的自动化运行时，可以用三种方式驱动同一套能力：

| 驱动方式 | 入口 | 适合 |
|---|---|---|
| 手动界面 | App 的「运行 / 脚本中心 / 日志 / 设置」 | 用户自己点按、配置、看状态 |
| JavaScript 脚本 | 脚本编辑器 + QuickJS 运行时 | 可重复的个人自动化 |
| 外部 AI / MCP | 「MCP 服务」暴露 HTTP 端点 | 由别的 Agent 读屏、点击、运行脚本 |

配置分成四层，排查时按顺序确认，**不要跳过系统授权直接怀疑 UI 开关**：

1. **系统授权层**：Android 权限、Shizuku / Root / 无线调试 / 无障碍服务。
   决定「这台设备能不能读到、能不能操作」。
2. **应用设置层**：设置页里的偏好（超时、截图压缩、通知、虚拟屏、日志等）。
   决定「运行时怎么表现」。
3. **脚本 / 任务层**：`@need`、`@env`、脚本级环境变量、订阅、定时任务、编排。
   决定「这一次脚本能调用哪些命名空间、何时触发」。
4. **外部接入层**：AI Agent 与 MCP 的开关。
   决定「别的 Agent 能不能接入、能调用哪些高危工具」。

四层之间没有自动联动：例如「已开启 Shizuku」不代表「MCP 的 Shell 工具已允许」；
「脚本没写 `@need`」也不代表危险命名空间一定可用，仍要对应开关打开。

## 1. 界面地图

底部有四个主标签；宽屏（≥600dp）时改为左侧导航栏。进入任意详情页时底栏隐藏，返回后恢复。

| 主标签 | 主要内容 | 典型入口 |
|---|---|---|
| **运行** | 权限概览卡片、设备信息、当前脚本与停止按钮、最近脚本快速运行、运行变量 | 点权限卡片 → 权限与能力；点最近脚本 → 直接运行 |
| **脚本中心** | 新建 / 导入 / 扫码导入 / 重命名 / 导出 / 删除、搜索、标签分组、批量多选、置顶、钉到磁贴、行内运行 | 条目行内播放按钮 → 直接运行（带 `@env` 先弹参数框）/ 运行中停止；条目菜单 → 脚本设置 / 标签 / 导出 / 删除；溢出菜单 → 定时任务 / 编排 / 排序 / 分组 |
| **日志** | 内存日志、级别 / 搜索过滤、清空与导出；虚拟屏状态卡片 | 点虚拟屏卡片 → 虚拟屏控制台（预览 / 应用 / 返回 / 键盘 / 截图 OCR / 诊断） |
| **设置** | 通用、自动化、扩展、安全、数据、关于与更新；顶部支持搜索 | 见下表 |

设置页的二级页面：

| 分组 | 二级页 | 内容摘要 |
|---|---|---|
| 通用 | 通用 | 主题、动态取色、纯黑背景、自定义主题色、语言、编辑器字号、自动保存 |
| 自动化 | 控制后端 | 读取 / 操作优先模式、按能力优先级、各后端启用开关 |
| 自动化 | 识别与截图 | 截图缩放 / JPEG 质量、OCR 本地或在线及服务商配置 |
| 自动化 | 脚本运行 | 运行超时、第二个脚本启动策略（拒绝 / 排队 / 终止）、保持唤醒、点亮屏幕、进度通知、快捷磁贴、音量键快速停止 |
| 自动化 | 通知 | 全局通知、脚本消息、运行结果策略、渠道管理 |
| 自动化 | 悬浮窗与虚拟屏 | 悬浮控制条、布局 / OCR 调试面板、后台虚拟屏与分辨率、画中画 |
| 自动化 | 环境变量 | 全局键值对，所有脚本共享 |
| 扩展 | AI Agent | OpenAI 兼容接口、生成参数、Agent 工具、系统提示词 |
| 扩展 | MCP 服务 | 服务开关、令牌、监听范围、端口、工具开关、安全黑名单 |
| 安全 | 权限与能力 | 设备授权总入口，见第 2 节 |
| 安全 | 安全解锁 | 自主解锁总开关、解锁方式、凭据、测试 |
| 数据 | 日志 | 自动清理、级别、大小、保留天数、缓存图片、性能基线 |
| 数据 | 录制管理 | 用户操作录制、录制列表、采样参数、删除 / 清空 |
| 数据 | 备份与恢复 | 导出 / 导入配置、恢复默认 |
| 调试 | 开发者选项 | 需在「关于与更新」连点版本号解锁，见 3.12 |
| 关于 | 关于与更新 | 版本、检查更新、自动检查、更新方式 |

其它详情页：脚本编辑器、脚本设置（名称 / 环境变量 / 订阅）、定时任务、编排、
蓝牙 HID 连接、无线调试配对、虚拟屏预览、录制详情、通知渠道编辑。
打开详情页时会话状态由导航层保持，返回主界面不会重置四个标签。

## 2. 系统授权层：权限与能力

入口：**运行 → 权限卡片**，或 **设置 → 权限与能力**。页面分「读取 / 操作 / 附加能力」三组，
同一权限可能出现在多个分组；授权状态由同一数据源驱动，撤销后立即同步。附加能力内部再分
**系统权限**（通知、悬浮窗、蓝牙、本地网络、精确闹钟、安装未知应用、后台保活）与
**脚本能力**（应用列表、脚本网络）。

顶部用「读取就绪 / 操作就绪」概括：任一读取后端可用即读取就绪，任一操作后端可用即操作就绪。

| 权限 / 能力 | 默认 | 作用 | 关闭或未授权的影响 |
|---|---|---|---|
| **屏幕捕获** | 关 | 一次录屏授权后持续提供屏幕帧，供截图 / 找图 / OCR | `captureScreen()`、`images.*`、`ocr.*` 需改走控制后端；无可用后端时失败 |
| **蓝牙 HID** | 未连接 | 通过外部 HID 硬件注入手势、按键、文本 | 少一个低风控输入后端；不能替代读控件树 |
| **无障碍** | 关 | 手势、文本、控件树（`selector.*`）、API 30+ 截图、Toast 读取（`notify.toasts/latestToast`）、事件读取（`events.*`，含按键观察） | 脚本无法使用 `selector.*`；失去控件树读取、一部分输入能力、Toast 读取与事件/按键观察 |
| **Shizuku** | 未授权 | 手势 / 按键 / 文本 / 截图 / Shell / 虚拟屏 / 特权解锁 | 失去 Shell、虚拟屏与最可靠的自主解锁 |
| **无线调试** | 未配对 | 与 Shizuku 同级的 Shell 能力，无需常驻 Shizuku | 失去 Shell；不提供虚拟屏与 Shizuku 特权解锁 |
| **Root** | 未授权 | 同 Shizuku 并带系统级操作 | 失去 Shell 与依赖系统权限的能力 |
| **通知监听** | 未授权 | 读通知、等待新通知、清除 / 点击 / 删除通知（`notify.list/latest/clear/click/delete`） | 通知监听类 API 不可用；不影响 `notify.toasts/latestToast`（依赖无障碍）与 `push.*` 发送 |
| **通知权限** | 未授权 | 显示脚本进度与本地通知（Android 13+ 运行时权限） | 通知不显示；进度与本地通知相关 API 仍返回成功但不可见 |
| **悬浮窗** | 未授权 | 悬浮控制条、布局 / OCR 调试面板、脚本 `floaty.*` | 无法显示悬浮窗与脚本悬浮 UI；截图与注入不受影响 |
| **蓝牙** | 未授权 | 扫描 / 连接蓝牙 HID（Android 12+ 用「附近的设备」，以下用定位） | HID 扫描与连接不可用 |
| **本地网络** | 未授权 | 局域网发现与连接（无线调试、MCP 等，Android 17+） | 无线调试配对 / MCP 局域网访问可能失败 |
| **精确闹钟** | 未授权 | 定时任务、编排、订阅准点触发（Android 12+） | 退化为非精确闹钟，可能延迟触发 |
| **安装未知应用** | 未授权 | 应用内下载并安装更新 | 更新会跳转系统设置，需手动授权 |
| **使用情况访问** | 未授权 | 前台应用与使用时长（`app.foreground/usageStats`） | 相关查询返回空或失败；定时任务的「指定前台应用」条件可能无法判定 |
| **应用列表**（开关） | 开 | 允许 `app.list/info/isInstalled` 枚举已安装应用 | 关闭后只能拿到有限应用信息 |
| **全部文件访问** | 未授权 | `fs.*` 与截图 / 找图可读写共享存储任意路径 | 仅应用私有目录与部分公共目录可用 |
| **脚本网络**（开关） | 关 | 允许 `http.*` 发起 HTTP(S) 请求；可填域名白名单 | 关闭后 `http.*` 不可用；白名单为空表示不限制主机 |
| **后台保活** | 未加入 | 把应用加入电池优化白名单 | 切后台 / 锁屏后可能被 ROM 回收，脚本与 MCP 连接会中断 |

补充规则：

- 核心后端（HID / 无障碍 / Shizuku / 无线调试 / Root）按**能力**协商，可混合使用。
  例如「无障碍读控件树 + HID / Shizuku 注入输入」。
- 「撤销权限」的语义由后端决定：HID 断开并清除记忆设备；无障碍调用 `disableSelf()`；
  Shizuku 断开后端并跳转 Shizuku；Root 撤回后端（彻底撤销需去 Magisk）；
  无线调试断开或在设置页「忘记配对」。
- 完整能力矩阵、风控与授权成本见 [CONTROL_MODES.md](CONTROL_MODES.md)。
- 脚本内可用 `permissions.*` 查询就绪状态，但**查询结果不改变授权**。

## 3. 应用设置层

### 3.1 通用

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 主题模式 | 跟随系统 | 仅影响界面配色 |
| 动态取色 | 开（Android 12+） | 用系统壁纸取色；不可用时隐藏或禁用 |
| 纯黑背景 | 关 | AMOLED 黑色背景，仅界面 |
| 自定义主题色 | 未设置 | 仅在关闭动态取色时生效；只改变界面 |
| 语言 | 跟随系统 | 简体中文 / English；切换会重建 Activity，不影响脚本 |
| 编辑器字号 | 13sp | 仅编辑器显示 |
| 编辑器自动保存 | 开 | 编辑时自动落盘；关闭后依赖手动保存 |

### 3.2 控制后端

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 读取优先模式 | 自动 | 多项读取能力可用时的全局优先后端；「自动」按注册顺序 |
| 操作优先模式 | 自动 | 手势 / 按键 / 文本等操作能力的全局优先后端 |
| 按能力指定优先模式 | 跟随全局 | 覆盖单项能力（如截图走 Shizuku、点击走 HID）；只列出至少两个可用后端的项 |
| 各控制后端启用开关 | 全开 | 关闭后该后端不参与能力协商；**已建立的连接本身不受影响**，重新打开后原有优先级继续生效 |

影响：决定同一脚本调用落到哪个后端。后端不支持某能力时会回退到其它已启用且就绪的后端；
都没有则返回失败。授权与撤销在「权限与能力」页，不在这里。

### 3.3 识别与截图

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 截图缩放 | 100% | 仅影响「保存截图到文件」与「在线 OCR 上传」；找图 / 找色 / 本地 OCR 仍用全分辨率，坐标不变 |
| JPEG 质量 | 90 | 影响保存文件大小与在线 OCR 流量 |
| OCR 模式 | 本地 MLKit | 本地离线、隐私好、耗算力；在线适合低端设备，失败自动回退本地 |
| 在线服务商 | 百度 / Google Vision / 自定义 | 决定 API Key、地域与返回坐标；自定义需请求地址与鉴权 Header |

### 3.4 脚本运行

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 运行超时 | 不限制（0） | 超过设定时长（10/30/60/120 分钟）中断脚本；可打断纯计算死循环 |
| 第二个脚本启动时 | 拒绝 | 拒绝 / 排队（单槽、后到覆盖）/ 终止当前；对所有触发来源生效，终止超时 15 秒后强制启动新脚本 |
| 保持唤醒 | 开 | 脚本与定时任务期间持有 `WAKE_LOCK`，避免息屏中断 |
| 同时点亮屏幕 | 关 | 仅在保持唤醒开启时可设；运行脚本时点亮屏幕 |
| 启用进度通知 | 开 | 允许 `notify.progress` 更新运行通知；关闭后该 API 返回 `false`，运行通知仍在 |
| 启用快捷磁贴 | 开 | 控制磁贴是否响应；未钉选脚本或关闭时磁贴不可用 |
| 启用音量键快速停止 | 关 | 脚本运行期间按所选音量键停止当前脚本；按键可选音量加 / 减 / 任一，方式可选单击 / 双击 / 长按 |
| 音量键触发按键 | 音量减 | 仅在快速停止开启后生效；脚本注入的音量键不会触发 |
| 音量键触发方式 | 单击 | 无障碍连接时可拦截按键、不改变音量；未连接时降级为单击监听音量变化，双击 / 长按提示先开启无障碍 |

通知权限：Android 13+ 需要 `POST_NOTIFICATIONS`，否则进度通知与本地通知不显示。

### 3.5 通知

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 通知总开关 | 开 | 关闭后所有通知类别停止发送 |
| 脚本消息 | 开 | 控制脚本 `push.send()` 一类主动消息 |
| 手动运行结果 | 开 | 界面 / 磁贴触发的结果通知 |
| 自动运行结果 | 开 | 定时 / 编排 / MCP 触发的结果通知 |
| 运行结果最低级别 | 失败（WARN） | 可选全部 / 仅失败 / 仅错误 |
| 编排只发汇总 | 开 | 多脚本编排默认一条汇总通知 |
| 逐步通知 | 关 | 开启后每一步都通知，噪音较大 |
| 附带错误尾部 | 开 | 失败通知附错误摘要 |
| 渠道 | 本地系统通知 | 另支持 Webhook / Bark / Telegram / ntfy / 钉钉 / 企微 / 飞书 / Server 酱 / PushPlus / Gotify |
| 单渠道开关 / 最低级别 / 事件 / 标签过滤 | 各自配置 | 决定该渠道接收哪些通知；支持发送测试 |
| 本地渠道 | 不可删除 | 系统通知渠道；远程渠道可编辑删除 |

敏感字段（Webhook 密钥、Bot Token 等）由 Keystore 加密，但会随配置备份以明文导出。

### 3.6 悬浮窗与虚拟屏

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 悬浮控制条显示方式 | 展开 | 不弹出 / 折叠 / 展开；脚本运行时自动显示日志，结束自动关闭 |
| 手动「显示悬浮控制条」 | 关 | 手动开启后常驻，脚本结束也不自动关闭；需要「显示在其他应用上层」权限 |
| 显示布局 / OCR 调试面板 | 关 | 可拖动调试面板，读取控件树、跑 OCR、画识别框；同样需要悬浮权限 |
| 允许后台虚拟屏 | 关 | 需要 Android 10+ 与 Shizuku；允许脚本以 `@env RUN_MODE=background` 或 `virtualScreen.start()` 后台运行 |
| 默认运行模式 | 前台 | 未指定 `RUN_MODE` 的脚本按此运行；只有允许集合内的模式会出现在选项里 |
| 后台分辨率 | 设备档位 | 设备档位长边超过 1920 时等比缩小并同步缩放 dpi；也可选 720P / 1080P / 自定义宽高与 dpi |
| 后台运行时自动画中画 | 开 | 停在运行页按 Home 时缩为系统 PiP；小窗只读 |
| 脚本运行结束后自动销毁 | 开 | 关闭后本次虚拟屏保留，跨脚本复用；需自行停止 |
| 尝试显示系统栏 | 关 | 虚拟屏是否显示状态栏 / 导航栏 insets；部分 ROM 会忽略 |

关键联动：

- 虚拟屏激活后，截图 / 找图 / OCR / 点击默认定向到虚拟屏。
- 虚拟屏上**不支持** `selector.*` 与无障碍控件树，应改用截图 / OCR / 坐标输入。
- 只有支持 display target 的后端（Shizuku / 无线调试 / Root）参与虚拟屏输入协商。
- 截图与触摸注入期间，悬浮控制条与调试面板会自动隐藏，完成后恢复，避免截入自身。
- 脚本用 `floaty.*` 创建的悬浮窗同样需要悬浮权限，按 `runId` 归属：脚本停止或新 run
  启动时自动清理，截图 / 点击前也会临时隐藏。
- 「日志 → 后台虚拟屏」进入控制台：预览置顶并支持全屏；右侧操作栏可选择应用（启动后显示
  应用图标）、返回、打开键盘输入、截图 / OCR；还可切换分辨率与查看诊断。键盘输入通过
  `input -d` / 剪贴板注入，不依赖虚拟屏弹出系统输入法。脚本运行中控制台只读；应用列表受
  权限开关控制。

### 3.7 安全解锁

| 开关 / 选项 | 默认 | 作用与影响 |
|---|---|---|
| 自主解锁 | 关 | 手动运行、定时任务、MCP 自动解锁前尝试唤醒并解锁 |
| 解锁方式 | 滑动 | 滑动 / PIN / 图案；PIN 仅数字，图案通过锁屏录制生成 |
| 锁屏录制 | 无 | 自动锁屏后用 `getevent` 读取真实触摸，支持图案 / 连续手势 / 多次点击 |
| 测试解锁 | — | 先主动锁屏再走完整解锁链路；凭据错误需手动解锁 |

依赖：Shizuku / Root；无线调试只有 Shell 回退，可靠性更低。未启用或凭据缺失时，
解锁型操作会被阻止或跳过。凭据经 Keystore 加密，**不写入日志、不参与配置备份**。
输错可能触发系统限流或清空，仅应在自有设备使用。

### 3.8 环境变量

全局 `KEY=值` 键值对，默认所有脚本共享。运行时合并顺序：
`@env` 默认值 → 全局变量 → 脚本级变量 → 运行时输入表单（后者覆盖前者）。
脚本内用 `env.get/has/all/mode` 读取，不需要 `@need`。

## 4. 脚本与任务层

### 4.1 `@need` 能力声明（脚本头部）

`// @need shell, fs` 只注册列出的高风险命名空间。可声明的有：
`shell`、`fs`、`notify`、`events`、`floaty`、`push`、`http`、`clipboard`、`ai`、`app`、
`selector`、`images`、`ocr`、`pipeline`、`record`、`virtualscreen`。

- 未写 `@need` 时暴露所有**已启用**的命名空间。
- `device`、`console`、`permissions`、`env`、`state`、`modules` 与全局输入函数
  （`click` / `swipe` / `captureScreen` 等）始终可用。
- 未知名称拒绝运行；缺少前置条件（如 `http` 未启用、Shell 后端未就绪）只告警。
- 这是「最小暴露」而不是安全沙箱；AI Agent 自身工具不受脚本 `@need` 限制。

### 4.2 运行参数与运行模式

- 脚本头部 `// @env KEY=默认值  说明` 会生成运行输入表单。
- 环境变量合并顺序见 3.8。
- `RUN_MODE` 可指定前台 / 后台：后台需要「允许后台虚拟屏」与 Shizuku。
- 脚本设置页的「使用全局环境变量」开关决定是否合并 3.8 的全局变量。
- 脚本设置页的「订阅」可填远程 URL 与拉取间隔；启用后按间隔同步脚本内容，
  失败只影响该订阅，不影响本地脚本。

### 4.3 定时任务与编排

定时任务（脚本中心溢出菜单）支持：

- 触发：定时一次 / 间隔 / 五段 Cron / 事件（充电、Wi-Fi 连接、解锁）。
- 条件：充电中、Wi-Fi、已解锁、指定前台应用包名；全部满足才执行。
- 失败重试次数与间隔；条件不满足或手动停止不消耗重试。
- 使用 `AlarmManager`，开机后自动重新注册；事件触发有 60 秒去抖。

编排（脚本中心溢出菜单）复用同一套触发与条件，额外有：

| 开关 | 默认 | 作用与影响 |
|---|---|---|
| 启用编排 | 开 | 关闭后不触发 |
| 执行顺序 | 顺序 | 顺序 / 随机（仅本次触发打乱，不改持久化顺序） |
| 某步失败后继续 | 开 | 关闭则遇错立即停止后续步骤 |

### 4.4 快捷磁贴

在脚本中心对某个脚本「钉到磁贴」，再到系统快捷设置添加本应用磁贴。
磁贴点击：已钉选脚本运行中 → 停止；其他脚本运行或空闲 → 按忙时策略启动已钉选脚本。未钉选或关闭 3.4 的「启用快捷磁贴」
时磁贴不可用。

## 6. 关键联动与副作用

排查「开关都开了但没生效」时，优先看这些跨模块规则：

1. **截图来源顺序**：虚拟屏帧 → 持续录屏 → 控制后端。截图压缩只影响保存与在线 OCR，
   MCP 截图不复用压缩设置，避免图像缩放而坐标不缩放。
2. **悬浮层自动隐藏**：任何脚本截图 / 找图 / OCR / 触摸注入都会临时隐藏悬浮控制条与调试面板，
   防止把悬浮窗截进画面或点错目标。
3. **虚拟屏目标**：虚拟屏激活后输入、截图、OCR 默认走虚拟屏；`virtualScreen.target('main')`
   可临时切回主屏。虚拟屏上 `selector.*` 不可用。
4. **能力而非后端**：一个脚本调用可能落到不同后端；关闭某个后端只是让它退出协商。
5. **`@need` 不是沙箱**：它只控制命名空间注册；输入、`device`、`permissions`、
   `captureScreen` 始终存在。真正的高危保护靠 Shell 策略、MCP 开关与系统授权。
6. **应用列表与脚本网络**是应用层开关：系统权限已授予也可能被这两个开关关掉。
7. **保持唤醒与后台保活不同**：前者是运行期 `WAKE_LOCK`，后者是电池优化白名单；
   长任务两者都需要。
8. **自主解锁的前置条件**：Shizuku / Root（或无线调试 Shell 回退）+
   已启用 + 凭据有效；锁屏上失败会阻止本次操作，不会继续执行。
9. **通知权限**：Android 13+ 未授予 `POST_NOTIFICATIONS` 时，本地通知不显示；
   远程渠道（Webhook / Bark 等）不受影响。
10. **MCP 令牌等同于设备控制权**：局域网模式请只在可信网络使用；令牌可随时重新生成。
11. **备份含明文密钥**：AI / OCR / MCP / 通知渠道密钥会随导出文件明文保存；
    锁屏 PIN / 图案、脚本、录制文件不导出。
12. **录制含隐私内容**：屏幕帧与控件文本可能包含密码或聊天内容，只在本机保存。

## 7. 给 AI Agent 的检查顺序

在替用户排查或操作前，按此顺序确认：

1. **接入**：MCP 是否启用、地址 / 端口 / 令牌是否正确、监听范围是否可达。
2. **授权**：读取与操作是否就绪；具体哪个后端可用；Shell 依赖哪个后端。
3. **工具开关**：需要 Shell / 脚本 / 解锁 / 录制控制时，是否已在 MCP 工具开关中显式打开。
4. **目标屏**：虚拟屏是否激活；当前操作目标是主屏还是虚拟屏。
5. **脚本约束**：脚本是否写了 `@need`；`http` / `app` 等应用开关是否打开；
   环境变量与 `RUN_MODE` 是否符合预期。
6. **执行安全**：优先用归一化坐标；不确定时用 `dry_run` 预演；超时返回
   `running` + `request_id` 时用 `get_result` 查询，**不要直接重试**，避免重复点击。
